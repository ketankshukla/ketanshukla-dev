MCP + RAG in Plain English

One project. One story. No jargon.

Ketan Shukla — ketanshukla.dev

The problem

You have a room full of documents — PDFs, notes, manuals, research papers — and you want to ask them questions like they are a person.

“What does our refund policy say about international orders?”

“Which paper mentioned the 47% improvement?”

“Summarize the safety section of the user manual.”

The AI by itself cannot open the filing cabinet. It can talk about documents in general, but it cannot look inside your documents.

RAG — the smart librarian

Forget the acronym. Think of a librarian.

  • Reads every book once. Documents are cut into small chunks.
  • Turns each chunk into a number. Similar ideas get similar numbers.
  • Stores the numbers in a vector database. A card catalog sorted by meaning, not title.

When you ask a question, it finds the chunks whose numbers are closest to your question and hands only those pages to the AI.

MCP — the front desk

The agreed way for the AI to ask the librarian

MCP lets the AI say:

“Please run the query_documents tool with the question: What is our refund policy?”

And the RAG system replies:

“Here are the three most relevant paragraphs.”

Build the tool once, describe it once, and any MCP-speaking host can use it. It is USB-C for AI.

How they work together

The whole flow in one breath

  • User asks a question.
  • The AI sees the query_documents tool.
  • The AI calls the tool.
  • The RAG system finds the right chunks.
  • The chunks go back to the AI.
  • The AI answers in plain English.

The AI never had to read the whole filing cabinet. It asked for the right pages and answered like an expert.

What you would build

A single Next.js project with one API route

  • Documents — PDFs, text files, or notes you upload.
  • Chunker — splits documents into small pieces.
  • Embedding model — turns chunks and questions into numbers.
  • Vector database — finds the closest matches.
  • MCP server — exposes a query_documents tool.
  • Host / UI — where you type the question and see the answer.

The demo line that lands

“I built a tool that lets an AI ask my documents questions. The AI does not know my documents by heart. It asks a RAG librarian, gets the right pages, and answers like it read them just now.”

Why this matters

  • It combines retrieval, embeddings, and LLM orchestration.
  • It is the architecture behind almost every AI assistant that reads private data.
  • Simple enough to explain in three minutes. Deep enough to impress a technical interviewer.

One-line recap

RAG = show the AI only the pages that matter.

MCP = the agreed way for the AI to ask for those pages.

The project = one MCP server, one RAG librarian, endless documents that can finally be questioned.
